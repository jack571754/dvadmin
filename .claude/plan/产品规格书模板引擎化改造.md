# 产品规格书模板引擎化改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将设计工单产品规格书的「模板」从散落在代码各处的硬编码魔法数字，重构为前后端共享的声明式 Schema，使新增一种提报模板 = 新增一份 JSON 配置，零改业务代码、零数据库迁移。

**Architecture:** 定义一份 `TemplateSchema` JSON（前后端共享，TS + Python 各一份对等实现），描述模板的行布局、字段行偏移、字段键、样式、必填规则、遮罩键。前端 Univer 的渲染/读写/收集/遮罩全部由 Schema 驱动；后端 `ProductSpec` 新增 `spec_data: JSONField` 存动态字段，`SaveProductSpecView`/`LoadProductSpecView` 的校验、保存、遮罩全部由 Schema 驱动。顺带修复 `live_stream`/`detail_page` 标签与底层数据字段错位的隐藏 bug。

**Tech Stack:** Django 5.2 + DRF + SQLite(WAL)；Vue 3 + TS + Univer Sheets；pytest（后端，新增）。

## 0. 现状问题清单（改造动机，供执行者对照）

执行前必须理解这些「为什么」，否则会把魔法数字又改回去：

1. **魔法数字 `15`（行/块）散落 40+ 处**：`row % 15`、`blockIdx * 15`、`autoResizeRows(..., 15)`、`getProductCoords` 内 `blockIndex * 15`。`15 = 1 标题行 + 14 字段行`。字段数 ≠ 14 的模板直接报废。
2. **字段行偏移 `blockStartRow + N` 散落 40+ 处**：`+1`=品牌、`+2`=昵称、`+4`=规格、`+6`=赠品、`+7`=满赠、`+8`=会员礼、`+11`=价格、`+12`=日期、`+13`=备注，读写各写一遍。
3. **致命隐藏 bug**：`TEMPLATE_LABELS`（`web/src/views/design_order/product_spec/constants.ts:3`）只改了标签文字。但读写代码统一用 main_image 偏移：`blockStartRow+5` 永远当 `efficacy` 存（`index.vue:1713, 2170`）。切到 live_stream 后，用户在"主播话术"格里填的内容被存进 `efficacy`、被当成功效校验。三模板标签与底层数据错位。
4. **后端字段映射只有 15/16 两种**（`backend/dvadmin/design_order/views.py:116-149`），只区分"有无活动结束日期行"，与 3 种 `templateType` 完全不对应。
5. **`ProductSpec` 模型字段写死 20 个**（`models.py:138-167`），新模板要"主播话术""上播时间"——无字段可存。
6. **校验规则硬编码**（`views.py:185-269`），`_do_save` 逐字段硬取（`views.py:352-463`）。

**一句话**：当前"模板" = `TEMPLATE_LABELS` 一个标签字典。增加新模板要同时改 6 个文件。改造后 = 加一份 JSON。

## 设计契约：TemplateSchema

前后端共享的 Schema 形状（TS 写法，Python 端等价 dict）：

```ts
interface FieldDef {
  row: number;            // 块内行偏移（1..rowsPerBlock-2），相对 blockStartRow
  key: string;            // 动态字段键，存入 spec_data；如 'brand' 'livestream_script'
  label: string;          // 该行标签文字
  style: FieldStyle;      // 样式枚举：'contentCenter'|'contentLeft'|'contentLeftShaded'|'editableCenter'|'editableDate'
  kind: FieldKind;        // 'text'|'longtext'|'mention'|'gifts'|'tier'|'dateRange'|'price'
  required?: boolean;     // 提交校验是否必填（仅 status=submitted 生效）
  maskKey?: string;       // 字段权限遮罩键，对应 MenuField(ProductSpec).field_name；省略则不遮罩
}

interface TemplateSchema {
  templateType: string;           // 'main_image' | 'live_stream' | 'detail_page'
  label: string;                  // 模板中文名
  rowsPerBlock: number;           // 含标题行 + 间隔行；如 main_image=15
  columnsPerBlock: number;        // 固定 6（1 标签列 + 5 商品列）
  fields: FieldDef[];             // 字段定义，长度 = rowsPerBlock - 2
  // 校验规则（驱动 validate_submission）
  validation: {
    requiredSubmissionFields: string[];   // 提报级必填：['name','shop']
    priceFieldKey?: string;               // 价格字段键，存在则校验 >0 数值
    dateRangeFieldKey?: string;           // 日期字段键，存在则校验非空
  };
}
```

**关键不变量**（测试要覆盖）：
- `fields.length === rowsPerBlock - 2`（扣标题行 + 末尾间隔行）
- 每个 `field.row` ∈ `[1, rowsPerBlock-2]` 且唯一
- `main_image` 的字段键/行偏移必须与旧硬编码完全一致（保行为零变化）

### main_image Schema（从旧硬编码反推，行为零变化）

旧偏移对照（`index.vue`）：
- row1=brand(contentCenter) / row2=nickname(editableCenter) / row3=fullName(contentLeft) / row4=spec(contentCenter) / row5=efficacy(contentLeft) / row6=gifts(editableCenter) / row7=满赠tier(editableCenter) / row8=memberGift(editableCenter) / row9=memberValue(editableCenter) / row10=sellingPoint(contentLeftShaded) / row11=price(editableCenter) / row12=dateRange(editableCenter) / row13=remarks(editableCenter)

字段键与旧 `_do_save` 取值键一致：`brand nickname fullName spec efficacy gifts thresholdA memberGift memberValue sellingPoint price startDate endDate remarks`。

遮罩键与旧 `ROW_TO_FIELD_MAP` 一致：`brand nickname full_name specification efficacy gifts threshold_a member_gift member_value selling_point price start_date remarks`（snake_case，对应 `MenuField(ProductSpec).field_name`）。

// web/src/views/design_order/product_spec/schema/index.ts
import { FieldDef, FieldStyle } from './types';
import { ALL_TEMPLATES } from './templates';

export type { TemplateSchema, FieldDef, FieldStyle, FieldKind } from './types';

const DEFAULT_TYPE = 'main_image';

export function getSchema(templateType?: string) {
	return ALL_TEMPLATES[templateType || DEFAULT_TYPE] || ALL_TEMPLATES[DEFAULT_TYPE];
}

export function getRowsPerBlock(templateType?: string): number {
	return getSchema(templateType).rowsPerBlock;
}

export function getColumnsPerBlock(templateType?: string): number {
	return getSchema(templateType).columnsPerBlock;
}

export function getFields(templateType?: string): FieldDef[] {
	return getSchema(templateType).fields;
}

export function getFieldByRow(templateType: string, rowInBlock: number): FieldDef | undefined {
	return getFields(templateType).find((f) => f.row === rowInBlock);
}

// 样式枚举 -> Univer stylesDict 中的样式名（与 constants.ts buildStylesDict 对齐）
export function styleToUniverStyleName(style: FieldStyle, theme: string): string {
	const map: Record<FieldStyle, string> = {
		contentCenter: `contentCenterStyle_${theme}`,
		contentLeft: `contentLeftStyle_${theme}`,
		contentLeftShaded: `contentLeftStyle_shaded_${theme}`,
		editableCenter: `editableCenterStyle_${theme}`,
		editableDate: `editableDateStyle_${theme}`,
	};
	return map[style];
}

// 兼容：旧代码用 TEMPLATE_LABELS[type][row] 取标签，改为 Schema 派生
export function getLabelByRow(templateType: string, rowInBlock: number): string {
	return getFieldByRow(templateType, rowInBlock)?.label || '';
}

    for f in get_fields(template_type):

    """遮罩键 -> 块内行偏移，供 LoadProductSpecView 遮罩使用。"""

## 新增模板的最终工作流（改造完成后）

改造完成后，新增一种提报模板（例如 `video_short` 短视频提报）只需：

1. 在 `backend/dvadmin/design_order/templates_schemas.py` 追加一个 `VIDEO_SHORT_SCHEMA` dict + 注册到 `TEMPLATES`。
2. 在 `web/src/views/design_order/product_spec/schema/templates.ts` 追加对等的 `VIDEO_SHORT_SCHEMA` + 注册到 `ALL_TEMPLATES`。
3. （可选）在 `web/src/views/design_order/product_spec/index.vue` 的模板选择下拉项里加一个选项。
4. （若需字段级权限遮罩）在系统菜单管理的 `MenuField(ProductSpec)` 中登记新遮罩键。

**零数据库迁移、零业务代码改动、零前后端接口改动。**
