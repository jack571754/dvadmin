# 设计工单模块 — 产品视角诊断报告

> 生成时间：2026-06-12
> 视角：用户旅程 · 业务价值 · 体验痛点 · 功能缺口

---

## 一、业务本质

设计工单模块服务于一个**具体业务场景**：

> 美妆品牌运营人员在电商活动前，需要将多个产品的促销配置（价格、赠品、满赠档位、会员权益等）整理为一份**标准化矩阵对比表**，提交给设计团队制作活动素材图。

核心价值链：

```
产品档案维护 → 创建活动提报 → 选产品/填配置/配赠品/设档位 → 保存草稿 → 正式提交 → 设计团队消费
```

## 二、当前产品能力地图

### ✅ 已有功能

| 能力 | 完成度 | 说明 |
|------|--------|------|
| 产品档案 CRUD | ★★★★ | 标准的增删改查 + 字段级权限 |
| 规格表可视化编辑 | ★★★ | Univer 电子表格呈现，但编辑路径受限 |
| 产品自动回填 | ★★★ | 选择主产品后自动填入品牌/全称/规格/赠品/价格等 |
| 赠品/档位/VIP 配置 | ★★☆ | 弹窗内标签式编辑，交互繁琐 |
| @ 产品引用 | ★★☆ | 存在但不可发现，条件苛刻 |
| 脚注自动生成 | ★★★★ | 扫描赠品/档位引用的产品昵称，自动追加备案全称 |
| 草稿保存/正式提交 | ★★★ | 有保存和提交，但缺自动保存和校验 |
| 提报历史管理 | ★★★ | CRUD + 复用复制 |
| 字段级权限遮罩 | ★★★ | 前后端均有实现，但两套机制不一致 |
| CSV 导出 | ★★ | 仅 CSV，无 Excel，无模板化输出 |

### ❌ 缺失功能

| 能力 | 业务必要性 | 说明 |
|------|-----------|------|
| 审批流程 | **高** | 提交后无审批，直接锁定归档，缺少审核把关 |
| 自动保存 | **高** | 复杂表单无自动保存，误关页面数据全丢 |
| 提交前完整性校验 | **高** | 可提交空白产品、缺失价格/日期的提报 |
| 提交后撤回/驳回 | **高** | 提交不可逆，无法修正错误 |
| 产品档案与规格数据对齐 | **高** | 档位/功效/VIP权益在档案中不存在，新产品无法自动回填 |
| 活动模板管理 | **中** | 模板类型仅一个标识字段，无模板CRUD |
| 协同编辑 | **中** | 多人不能同时编辑同一提报 |
| 操作日志 | **中** | 谁改了什么无据可查 |
| 数据看板 | **低** | 无提报统计、产品热度、活动趋势等分析 |

## 三、用户旅程中的核心卡点

### 卡点 1：新建提报入口不直觉

**现状**：用户必须先去"提报历史"页面 → 点新增 → 填表单（名称+店铺+模板）→ 才能跳转到编辑页。也可以直接访问 `/product_spec` 创建无名提报，两条入口体验不一致。

**影响**：新用户上手困惑，不知道从哪开始。

**建议**：
- 统一入口为编辑页，首次进入时弹出提报信息填写
- 或在历史列表页提供更醒目的"新建提报"引导

---

### 卡点 2：表格编辑体验与用户预期严重脱节

**现状**：Univer 电子表格占据了 80% 的页面视觉，但**所有单元格直接编辑都被拦截**（`params.cancel = true`）。点击单元格不是编辑，而是弹出一个结构化表单弹窗。表格本质上只是一个**只读的数据回显区**。

**影响**：
- 用户本能地想直接在格子里打字（Excel 习惯），却被告知"需要弹窗编辑"
- 表格的视觉暗示与实际交互不匹配，造成认知负担
- 弹窗遮盖表格，用户无法边看边改

**建议**：
- **短期**：在表格区域增加明确的"点击编辑"提示（如单元格 hover 态、工具提示）
- **中期**：允许部分字段直接在单元格内编辑（如价格、日期），仅复杂字段（赠品/档位）走弹窗
- **长期**：重新设计为"表单优先"布局，表格仅做预览/对比视图

---

### 卡点 3：@ 引用功能几乎不可发现

**现状**：在满赠档位行（row%15==7 或 8）输入 `@` 才能触发产品选择弹窗。但：
- 没有 UI 提示告诉用户"这里可以输入 @"
- 只在特定行生效，其他行输入 @ 无反应
- 全局 input 事件监听与 Univer 内部状态同步容易出错

**影响**：90% 的用户不会发现这个功能，导致满赠行只能手动输入产品名。

**建议**：
- 在可引用的单元格中显示占位提示（如"输入 @ 引用产品"）
- 或改为点击按钮触发选择器，不依赖隐晦的输入触发
- 最优解：档位行直接显示"添加引用"按钮

---

### 卡点 4：没有自动保存 — 最大的数据丢失风险

**现状**：用户必须手动点击"保存草稿"。一个提报通常包含 5-10 个产品，每个产品 15+ 个字段，填写时间可能超过 30 分钟。期间任何意外（误关页面、浏览器崩溃、网络中断）都会丢失所有未保存的修改。

**影响**：用户不敢长时间编辑，频繁手动保存打断工作流；一旦丢失，重新填写的时间成本极高。

**建议**：
- **最低要求**：5 分钟自动保存 + 页面关闭前弹窗提醒
- **更好**：每次修改后自动保存（如 Notion/Google Docs 的实时保存）
- **最佳**：显示"上次保存于 xx:xx"时间戳 + 草稿版本历史

---

### 卡点 5：产品档案与规格表数据断层 — 自动回填覆盖不全

**现状**：产品档案（`ProductArchive`）只存储基础信息（名称、规格、品牌、零售价、赠品）。但规格表需要的**功效、满赠档位A/B、会员权益、卖点**等字段在档案中根本不存在。这些字段只会从前端硬编码的 `PRODUCT_DATABASE`（5个产品）获取。

**影响**：
- 后端新增的产品档案，功效/档位/VIP 等字段为空，用户必须每次手动填写
- 硬编码的 5 个产品数据与后端可能不同步（日期已过时）
- 产品越多，手动填写量越大，自动化价值被稀释

**建议**：
- **核心修复**：扩展 ProductArchive 模型，增加 efficacy、selling_point、default_threshold_a/b、default_member_gift 等字段
- 前端删除 `PRODUCT_DATABASE` 硬编码，统一从后端 `/dict/` 获取
- 新建产品档案时引导用户填写完整信息

---

### 卡点 6：正式提交没有完整性校验

**现状**：提交只校验提报名称不为空。用户可以提交：
- 空白产品列（有列但没填昵称）
- 缺失价格的提报
- 没有活动日期的提报
- 赠品格式错误的提报

提交后不可逆，无撤回/驳回机制。

**影响**：设计团队可能收到不完整的提报数据，返工成本高。

**建议**：
- **提交前必填校验**：昵称、品牌、价格为必填；日期格式校验
- **提交前预览**：显示即将提交的产品清单和完整性报告
- **提交后撤回**：允许 24 小时内撤回（转为草稿）
- **接入审批流**：提交进入审批流程，审核通过后才锁定归档

---

### 卡点 7：审批流程完全缺失

**现状**：项目已集成了 `dvadmin3_flow` 工作流审批引擎（可视化流程设计、条件分支、审批人路由、WebSocket 通知），但设计工单**完全没有接入**。提交后直接锁定，没有审核把关。

| 对比项 | 审批引擎能力 | 设计工单现状 |
|--------|-------------|-------------|
| 模型继承 | `FlowBaseModel` | `CoreModel` |
| 流程状态 | 待审核/通过/驳回/撤回 | 仅草稿/已提交 |
| 审批人路由 | 按角色/部门/指定人 | 无 |
| 驳回修改 | 支持 | 不支持 |
| 消息通知 | WebSocket 推送 | 无 |
| 审批记录 | FlowRecord 可追溯 | 无 |

**影响**：
- 运营提交错误数据无法被拦截
- 主管无法审核确认活动配置
- 没有审批记录，出问题无法追溯

**建议**：
- `ProductSpecSubmission` 继承 `FlowBaseModel`
- 配置审批流程：运营提交 → 主管审核 → 设计确认
- 利用已有的 `dvadmin3_flow` 能力，开发成本低

---

### 卡点 8：赠品/档位配置体验繁琐

**现状**：
- 每次添加赠品需：点"添加赠品"→ 输入搜索词 → 从下拉选择 → 搜索框自动关闭
- 连续添加多个赠品需反复点按钮展开搜索框
- 档位只有 A/B 两档，无法灵活增减（前端代码中写死了两档渲染）
- VIP 赠品与标配赠品是两个独立区域，相同产品需重复添加

**影响**：每次编辑赠品配置的交互成本高，打断工作流。

**建议**：
- 赠品搜索框选择后不自动关闭，支持连续选择
- 档位支持动态增减（已部分实现但交互不直观）
- 统一赠品选择器，添加时可选择"标配/VIP/档位"分类

---

### 卡点 9：提报历史页功能单薄

**现状**：
- 列表只展示名称、店铺、状态、创建时间
- 无筛选/搜索/排序功能（虽然后端支持但前端未配置）
- 编辑按钮文本"修改名称"，但实际可改所有字段
- 没有批量操作（批量删除、批量提交）
- 没有提报统计（本月提报数、草稿/已提交占比）

**建议**：
- 完善筛选/搜索/排序
- 区分"修改名称"和"编辑详情"操作
- 增加提报数据统计概览
- 支持批量操作

---

### 卡点 10：数据消费端缺失

**现状**：提报数据提交后，下游（设计团队）如何消费？
- 没有"设计任务分发"功能
- 没有"素材确认/反馈"闭环
- CSV 导出是唯一的数据出口，格式不友好
- 没有"提报详情预览"页面（非编辑态的只读展示）

**影响**：数据提交后流转断裂，设计团队可能仍需手动复制信息到设计工具。

**建议**：
- 增加提报只读预览页（适合分享给设计团队）
- 提供"复制为图片"功能（直接粘贴到设计稿）
- 探索与设计工具的集成可能性

## 五、总结

### 一句话诊断

> **设计工单模块完成了"数据录入"的基础建设，但在"数据保障"（自动保存/校验/审批）和"数据消费"（预览/分发/反馈）两端存在明显缺失，中间的"编辑体验"也与用户预期存在差距。**

### 三大核心问题

1. **安全网缺失**：没有自动保存、没有提交校验、没有审批流程、没有撤回机制 — 用户的每一步操作都在走钢丝
2. **自动化半成品**：产品档案与规格表数据不对齐，自动回填只覆盖了部分字段，新产品的手动填写量仍然很大
3. **交互体验与预期脱节**：表格占了主要视觉但不可直接编辑，@ 引用不可发现，赠品编辑繁琐，日期用手打

### 推荐的第一步

**先修安全网（自动保存 + 提交校验），再接审批流，最后优化编辑体验。**

因为：没有自动保存和校验，再好的编辑体验也没有意义 — 用户的数据随时可能丢失或提交不完整的数据。
