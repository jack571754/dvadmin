# 纯 DVAdmin 范围与前端升级规划

更新日期：2026-10-24。以下规划以本次业务清理后的代码为基线。

> 后续深度规划见 [前端重构详细设计](frontend-refactor-design.md) 与 [实施任务清单](frontend-refactor-backlog.md)。本页保留业务清理及初版规划记录；完整工程范围和估算以详细设计为准。

## 保留范围

- 系统管理：用户、部门、角色、菜单、按钮权限、字段权限。
- 通用配置：系统配置、字典、地区、文件、接口白名单。
- 消息中心、下载中心、登录日志、操作日志、个人中心。
- 通用插件：Celery 定时任务、工作流设计和审批引擎，包括移动审批渲染组件。
- Vue 3、TypeScript、Vite、Pinia、Element Plus、FastCrud 的现有基础设施。

## 本次移除

设计工单、商品档案、规格提报、个人履历与作品集、测试商品/博客/请假模块的前后端源码、应用注册及路由入口已移出项目。移除仅供商品规格页使用的五个 Univer 直接依赖，并同步 pnpm 锁文件。数据库中的 8 个业务菜单及关联权限已清理；12 条请假、报销测试流程已下架并软删除。业务表、工作流历史、用户和角色保留。

清理后 `web/src/views` 有 135 个 Vue 文件（含子组件，不等于页面数），27 份 CRUD 配置；本机数据库保留 27 个系统及通用插件菜单。

### 其他环境的菜单清理

在 backend 目录运行，默认只预览：

```powershell
python manage.py retire_custom_business
python manage.py retire_custom_business --apply --backup-dir E:/backups/dvadmin
```

命令根据业务组件/路径查找菜单，并递归清理后代及关联权限。只下架关联模型或已确认名称的测试流程，不删除审批记录。应用变更前自动执行 SQLite 在线备份；非 SQLite 数据库会拒绝执行，须先设计对应备份方案。不要执行 `flush`、业务应用反向迁移或删除陈旧 ContentType，避免损坏保留数据。

本机源码、工作区差异和 SQLite 一致性备份：
`E:/project/管理后台/dvadmin-backups/core-only-20261024-203239/`。
`retired-source/` 保存移出的原目录；`source.zip` 保存清理前源码；`working-tree.patch` 保存清理前未提交差异；`db.sqlite3` 保存清理前数据库。

恢复须停止写入数据库，先备份当前状态，在临时目录解压源码并选择性恢复，恢复对应应用注册与依赖；恢复数据库时一并处理该库现有 WAL/SHM 文件，不能只覆盖正在使用的数据库主文件。

## 新的技术路线

优先在现有 Vue 3 + Element Plus + FastCrud 上升级布局、反馈和可维护性。借鉴 Vben 的导航和设计规范；先不整体迁移 Vben，也不切换 React。shadcn-vue 限于独立原型评估，在确认 Tailwind、主题、弹层与键盘焦点兼容后再决定是否采用。

新试点为用户管理和角色授权：分别覆盖列表搜索、表单、部门关联，以及菜单/按钮/字段权限。替代原商品提报试点，不再按已移除业务估算。

## 实施阶段与验收

| 阶段 | 内容 | 验收 | 工程人日 |
| --- | --- | --- | --- |
| 1. 基线与设计 | 常用路由、权限矩阵、桌面与窄屏布局；记录加载及筛选响应 | 基线清单和可评审的首页/列表/授权原型 | 2–3 |
| 2. 公共布局 | 导航、标签、面包屑、主题变量、间距、组件密度；扩展现有菜单搜索 | 键盘可操作，缩放/窄屏无主要遮挡，深色模式可读 | 3–4 |
| 3. 用户与角色试点 | 搜索条件恢复、错误定位、保存反馈、授权操作；拆分职责 | 管理员与普通角色下查询/编辑/授权正确，后端拒绝越权 | 3–5 |
| 4. 批量推广 | 通用 CRUD、配置、消息、日志、Celery 和审批入口；首页使用真实信息 | 主要页面操作与反馈一致，原插件和国际化可用 | 4–5 |
| 5. 回归交付 | 构建、权限与关键流程自动化、网络失败恢复、打包和历史主题兼容 | 可部署版本、验证报告和回退说明 | 2–3 |

初版基础体验范围估算为 **14–20 工程人日**。后续详细设计补充权限初始化、测试环境修复、连接生命周期与回退验证，完整范围调整为 **22–32 工程人日（含缓冲）**，以详细设计为准，不能将两者视为同一交付范围。估算不是 AI 实际运行时间承诺。完整移动端重做、后端业务规则重构与整体 Vben 迁移另行评估。

AI 可维护性要求：为接口和权限定义明确类型；复杂状态移入 composables；组件有可运行示例；避免将所有业务塞入一个页面或继续增加深层 schema 封装；锁定依赖并保留关键流程自动化验证。
