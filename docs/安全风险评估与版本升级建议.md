# DVAdmin 项目安全风险评估与框架版本升级建议

> 评估日期：2026-10-24
> 评估范围：`django-vue3-admin-master`（Django 5.2.3 + Vue 3.5.31）全栈依赖、配置与代码
> 扫描工具：`pip-audit 2.10.1`（后端）、`pnpm audit`（前端）、官方安全公告交叉验证
> **结论：强烈建议立即升级。当前存在被野外主动利用的高危漏洞（CVE-2026-1207），且两大核心框架均已失去安全支持。**

---

### 2.2 最紧急的 3 个后端漏洞

#### 🔴 CVE-2026-1207 — Django SQL 注入（**已被野外主动利用**）
- **影响版本**：Django 5.2.0 ~ 5.2.10 → **项目 5.2.3 命中**
- **修复版本**：5.2.11+（建议直接升 5.2.18）
- **危害**：未授权攻击者可读取/篡改数据库，官方机构已发布"正在被积极利用"预警
- **来源**：NVD PYSEC-2026-44 / GHSA-mwm9-4648-f68q

#### 🔴 CVE-2026-15307 — Django 空间查询文件写入 + SSRF（HIGH）
- 影响 ≤5.2.16，修复于 5.2.17；具备远程代码执行可能性

#### 🔴 CVE-2026-33033 / 33034 — Django ASGI 文件上传内存耗尽（DoS）
- 影响 ≤5.2.12，修复于 5.2.13；**项目未配置 `FILE_UPLOAD_MAX_MEMORY_SIZE`，放大风险**

其余 Django 漏洞还包括：CVE-2026-87975（表单集越权）、CVE-2026-84429（HTTP 头解析 DoS）、CVE-2026-15920（admin XSS）、CVE-2026-6873/7666/8404（缓存与邮件）、CVE-2025-64458/64459/64460（Windows 路径、SQL、模板）等。

## 三、前端漏洞详情（pnpm audit 实测）

**总计 111 个：1 critical、53 high、49 moderate、8 low**

### 3.1 直接依赖受影响清单

| 包 | 当前 | 漏洞数 | 修复版本 | 关键问题 |
|----|------|--------|---------|---------|
| **axios** | 1.14.0 | **34**（14 high） | **≥1.20.0** | 原型污染导致 MITM、凭据泄露、SSRF、ReDoS |
| **vite** | 5.4.21 | **8**（2 high） | **≥6.4.4** | **Windows 特有**：`server.fs.deny` 绕过可读取 .env；launch-editor 绕过 |
| **postcss** | 8.5.x | 4（2 high） | ≥8.5.23 | 任意文件读取、路径遍历 |
| **qs** | 6.15.0 | 3 | ≥6.16.0 | DoS（可被远程触发） |
| **echarts** | 5.6.0 | 1 | ≥6.1.0 | XSS |
| **js-cookie** | 3.0.5 | 1 high | ≥3.0.7 | cookie 原型劫持导致会话失窃 |
| baseline-browser-mapping | - | 1 | ≥2.11.0 | 构建期（dev only） |

### 3.2 最紧急的前端漏洞

#### 🔴 CVE-2026-53571 — Vite `server.fs.deny` Windows 路径绕过（HIGH 8.2）
- 影响 **Vite < 6.4.3**（含全部 Vite 5）
- **项目正运行在 Windows 上，开发服务器 8200 端口对外监听 `0.0.0.0`**
- 攻击者可通过 `/.env::$DATA?raw` 或 Windows 8.3 短文件名直接读取 `.env`、证书等敏感文件
- 修复：Vite ≥ 6.4.4

#### 🔴 axios 原型污染链（CVE-2026-44494 / 44496 / 27152 等）
- 影响 < 1.16.0 至 < 1.20.0 多个区间，**项目实际安装 1.14.0**
- 危害：攻击者可通过原型污染接管代理 → 完整 MITM（拦截、修改、窃取所有 HTTP 流量含认证凭据）
- 修复：**axios ≥ 1.20.0**

#### 🔴 js-cookie 3.0.5 原型劫持（HIGH）
- 项目直接使用 `js-cookie` 存储认证 token（`web/src` 中广泛使用）
- 修复：≥ 3.0.7

### 3.3 关键结论：Vite 5 已 EOL

官方 Support Versions 页面明确：

> 定期补丁：`vite@8.3`；重要修复与安全补丁：`vite@7.3`、`vite@8.2`；安全补丁：`vite@6.4`、`vite@8.1`。
> **之前的所有版本都不再支持。如果你使用的是 Vite 5.x，它是不支持的。**

Vite 8.0 已于 2026-03-12 发布（Rolldown 内核，构建提速 10-30 倍），8.1 于 2026-06-23 发布。

## 四、项目配置风险（非依赖）

| # | 问题 | 位置 | 风险 |
|---|------|------|------|
| 1 | `DEBUG = True` | `backend/conf/env.py:27` | 生产暴露堆栈、SQL、源码路径 |
| 2 | `ALLOWED_HOSTS = ["*"]` | `conf/env.py:37` | Host 头攻击、缓存投毒 |
| 3 | `SECRET_KEY` 硬编码（`django-insecure-` 前缀） | `settings.py:31` | Cookie/会话/JWT 签名可伪造 |
| 4 | `CORS_ORIGIN_ALLOW_ALL = True` + `ALLOW_CREDENTIALS = True` | `settings.py:203-205` | **任意站点可携带凭据跨域调用 API** |

| 11 | 密码策略：MD5 预哈希 + 历史默认弱密码（已移除，初始化密码为不可用值） | `system/models.py:97` | MD5 已不安全；首次使用需 `manage.py changepassword` 设置密码 |

## 六、工程与供应链风险

1. **`requirements.txt` 与实装严重脱节**（最危险的工程问题）
   - 声明 Django 4.2.14，实际 5.2.3；14 项版本不符
   - 8 个运行必需包未声明：`celery`、`django-celery-beat`、`django-celery-results`、`django-redis`、`pandas`、`numpy`、`pyjwt`、`django-import-export`
   - 声明了未安装的 `psycopg2`、已废弃的 `dvadmin3-celery`、`six`
   - **后果：任何新环境按 requirements 安装都会失败或装错版本**

2. **前端 package.json 声明 `@great-dream/dvadmin3-celery-web`**（文档称已移除），实际仍安装

3. **无锁定/无审计流程**：后端无 `pip freeze` 锁定，无 `pip-audit`/`safety` CI 检查；前端有 lock 但无人审计

4. **Node.js 已从系统移除**：`node`/`npm`/`npx` 全部不可用，前端只能靠 DSH 内置运行时启动，团队新人无法直接开发

5. **TypeScript 4.9.5**（最新 5.x）：与 Vite 6+/7 的类型定义不兼容，升级 Vite 时必须同步升级

cd web

**同时立即修改配置**（不需重启代码逻辑）：
```python

ALLOWED_HOSTS = ["your.domain"]  # 白名单
LOGIN_NO_CAPTCHA_AUTH = False

# settings.py

SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
```

### P1 — 2 周内（前端 Vite 升级，需回归测试）

| 方案 | 风险 | 说明 |
|------|------|------|
| **A. Vite 5.4.21 → 6.4.4**（推荐） | 低 | 修复全部已知 Vite CVE；`@vitejs/plugin-vue` 需 ≥5；TS 可仍用 4.9；配置改动极小 |

### P2 — 1~2 个月（框架主线升级 + 工程治理）

4. **清理和修复审批模块**（见第五章第 5/6/7 项）
5. **迁移数据库**：SQLite → PostgreSQL（并发、备份、审计）
6. **补充 Node.js 环境**：安装 Node 22 LTS 并写入项目 `.nvmrc` / `engines`

## 八、结论

**需要更新，而且不能再拖。**

1. **立即（今天）**：Django 5.2.3 → **5.2.18**。CVE-2026-1207 是"已被野外主动利用"的 SQL 注入，且项目版本正好在受影响区间，这是当前最大的单点风险。
2. **立即（今天）**：axios → 1.20.0+、js-cookie → 3.0.7+。两者都直接参与认证凭据传输。
3. **本周**：关闭 DEBUG、收紧 CORS/ALLOWED_HOSTS、SECRET_KEY 外置、恢复登录验证码、限制 Vite 监听地址。
4. **两周内**：Vite → 6.4.4（Vite 5 已 EOL，Windows 环境下存在可直接读取 `.env` 的 HIGH 漏洞）。
5. **中期**：Django → 6.2 LTS，重建依赖清单与 CI 安全门禁。

不建议的做法：直接把 Django 升到 6.1 / Vite 升到 8 一次性完成——`django-comment-migrate`、`drf-yasg`、`django-restql` 与 Rolldown 迁移都会引入非预期故障，应分阶段推进并在每阶段跑通现有审批测试流（`scratch/flow_test/run_flow_test.py` 可作为回归基线）。
