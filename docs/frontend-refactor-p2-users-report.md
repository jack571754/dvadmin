# P2 首批：用户列表与响应式操作权限

日期：2026-10-25。承接 [HTTP 内核批次](frontend-refactor-p1-http-report.md)，推进 B14、B15 的列表/状态操作与 B08 的试点 CRUD 权限快照。保留现有 Vue、Element Plus、FastCrud、URL/API 和表单，没有对业务数据库执行写入测试，也没有提交 Git。

## 本批行为

- 用户与角色的新增、编辑、删除等按钮使用响应式权限；状态开关按 Update 权限禁用。提交同一行时防重，使用行副本请求下一状态，服务端成功后才切换，失败保持原值，不自动重试。
- 用户列表的新查询取消旧请求，旧响应即使忽略 abort 也不能生效；相同进行中查询只请求一次。筛选回到第 1 页，普通刷新与分页保持上下文。
- 在 FastCrud 绑定回调前包装 doRefresh，覆盖分页、工具栏、搜索和表单后的列表刷新；失败保留已有结果与输入，提供局部重试，取消不弹失败或冒出未捕获 rejection。
- 重复选择当前状态/部门不再次查询；快捷搜索清空通过 mergeForm:false 移除旧参数。高级重置清空文本和高级条件，保留部门/状态范围。
- 默认列表与部门树独立加载；恢复的部门 ID 先与当前可访问部门核对，不存在则回到全部范围。离开页面取消查询，KeepAlive 返回时恢复此前被取消的查询，卸载后禁止新请求。
- sessionStorage 的 `dvadmin:users:list:v1:<accountId>` 白名单仅保存部门、状态、页码、页大小和允许的排序参数。文本/个人信息条件不写入；有文本或其他高级条件时保存的页码回到 1。非法内容和不可用存储不阻断查询。
- 修复语言切换时用空配置重建 CRUD 的问题，保留数据、筛选、分页、排序及用户高级面板；复用翻译函数与行提交状态。
- 角色页不再初始化即请求全部用户；已有分配弹层在明确打开时加载。会话变化或角色页卸载时清空旧角色抽屉、用户选择及按钮/字段状态。

没有改动 node_modules。偏好与调度分别位于 `features/users/listState.ts`、`shared/composables/latestRequest.ts`，行提交控制位于 `shared/composables/rowMutation.ts`。旧菜单入口及表单 validators 保留。

## 边界与后续

本批不是 B14/B15 或 P2 的整体验收。部门树和列表尚未全部拆分组件；高级筛选全部字段、排序指示器、键盘/移动端、字段权限及列设置仍需专项验证。sessionStorage 支持当前标签页刷新恢复；完整登出仍按 Session.clear 清空它，不承诺跨登出永久保存。

状态开关的防重与失败保留不代表新建/编辑/删除/重置密码、导入导出完整流程已覆盖。已打开表单的权限变化、角色抽屉的菜单即时保存/字段草稿和未保存确认也未完整迁移。后端仍是授权边界。

角色列表尚未接入用户列表的 latest-request 流程；角色分配用户及菜单/字段授权的竞态、失败恢复、事务边界仍属 B17/B18。英文上下文有用户页证据，不代表三语言全站验收。

后续用户新建/编辑提交防重、失败内容保留及字段权限适配已在 [表单批次](frontend-refactor-p2-forms-report.md) 交付，边界以该记录为准；接下来推进角色授权草稿。P1 的精确组件注册、WebSocket/版本检查、全布局/插件验收也仍有未完成项，不据此向 P3 批量推广。

回退使用上一前端制品，接口、菜单路径和业务数据兼容，旧前端可忽略版本化偏好键。不要使用全仓 reset 覆盖其他批次，也不以数据库回滚撤销已成功提交的业务操作。
