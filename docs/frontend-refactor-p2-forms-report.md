# P2 用户表单与字段权限批次

日期：2026-10-25。承接 [用户列表试点](frontend-refactor-p2-users-report.md)，推进 B15/B16。继续使用 Vue、Element Plus 和 FastCrud；未提交 Git。

## 本批行为

- 新建、编辑提交防重；请求期间禁用重置、取消及关闭。失败保留输入，展示字段错误并定位输入框，用户主动重试；密码仅在请求副本中编码，失败重试不会重复编码。
- 打开和提交表单时读取字段权限，提交前再次核对操作权限。权限变化时阻止写入并保留输入；字段读取失败提供重试，页面不会先展示未过滤列表。
- 字段权限只收紧原配置，保留校验、组件及原有隐藏设置。查询、新建、编辑权限分别处理；列设置无法恢复禁止查询的字段。
- 提交副本采用已知表单字段白名单，排除派生数据和额外权限字段；编辑不提交密码，明确禁止写入的字段不进入请求。
- 用户列偏好按账号隔离保存在 sessionStorage，读写时重新应用字段限制。没有持久化表单草稿或密码。
- 抽出纯字段适配、表单会话、请求副本和列偏好模块；共用 columnPermission 适配器保留原表单配置。
- 用户后端原先没有字段读取路由。本批复用已有 FieldPermissionMixin 暴露 `/api/system/user/field_permission/`，没有新增模型、迁移或修改写入授权规则。部署时需同时发布这两行后端适配。

## 边界与后续

字段接口空对象或缺少字段表示未配置，沿用页面既有设置；只有显式 false 才收紧，不能把缺少条目推断为全面拒绝。畸形响应则拒绝继续。

前端适配不是安全边界。后端目前没有全面强制执行新增/编辑字段权限，更新仍使用 PUT 完整校验：若被禁止的字段也是后端必填字段，请求可能被拒绝；表单会保留输入并反馈错误。本批没有绕过限制，也没有宣称后端字段级授权已经完成。

B15 的删除、重置密码、导入导出及完整键盘/窄屏流程仍需专项处理。共用适配器有单元覆盖，不代表地区、日志、下载等旧页面全部验收。表单未保存关闭确认尚未覆盖。B16 也未整体验收；下一批推进 B17/B18 的角色授权上下文、字段草稿及失败恢复，P2 尚未完成。

回退使用上一前端制品；新增只读接口可保留，旧前端忽略版本化列偏好键。不要用全仓 reset 覆盖已有工作，也不要回滚数据库撤销已成功的业务写入。

后续进展：删除/重置防重、表单未保存关闭确认、用户导入及筛选导出已在 [操作批次](frontend-refactor-p2-operations-report.md) 推进；本报告中的未完成边界按该后续记录核对。
